# EvoResearch · Loop 总控规则

> 每个阶段开工第一件事：读本文件 + `loop/progress.log`。
> 推进的唯一依据是 `progress.log` 里的「[时间] <阶段> · 完成」。

## 二、全局铁律

1. **全程自主推进**，不要停下来反问；遇到分歧按任务书推荐做法处理，并把决策写进成果文档。
2. **实验必须真跑**。不许编造数字、不许写死结果、不许用 mock 冒充。
3. **测试集只能评一次**。调参只用训练/验证集。
4. **不许删库、不许 `git reset --hard`、不许动别人的未提交改动**。
5. **不许放宽测试断言来凑通过**。测试掉了就是没完成。
6. **不许把密钥写进代码、文档、日志**。只从环境变量读。
7. **不许把 `reverted` 当成"删掉"**：被回滚的轮次仍是证据（假设被否证），必须留痕。

## 三、上下文纪律

每完成一个里程碑（一次提交、一个测试通过、一轮实验跑完）：
- 跑一次全量测试：`.venv\Scripts\python.exe -W error::ResourceWarning -m unittest discover -s tests`
- 基线数只许涨不许跌（当前 **97 passed**）

如果连续改了三处还没跑测试，停下来先跑。
如果一个文件改到 600 行还没跑通，先提交能跑的部分再说。

## 四、每阶段收尾四件套（缺一不算完成）

1. 成果写进 `HANDOFF.md`（含真实测试读数）
2. `git add <具体文件>` + commit（**不要 `git add -A`**）
3. 在 QQ 群回一句：做了什么、测试数、关键读数
4. 向 `loop/progress.log` 追加一行：`[时间] <阶段> · 完成`
