# M1 · EvoUndo 版本链（能自动回到最优，且能点开看）

## 〇、本阶段人话目标

现在系统会判"这轮退步了"（`reverted: True`），但**它没有真的回到上一代**——
`best` 只是内存里一个变量，进程一退就没了，也没有版本概念。

这一阶段要做出：**每次实验都是一个版本，退步就自动把 current 指回 best，而且能列出/回放任意一代**。

验收时演示给评委看的画面应该是：跑到第 3 轮退步 → 系统自己退回第 2 轮 → 屏幕上能列出 v1/v2/v3 和各自的分数。

## 一、口径

- **版本 = 一次实验**（一次 `Experimenter.run` 的结果），不是"一次代码提交"。
- **回滚 = 把 current 指向某个历史版本**，不重新训练。因为每一版的参数和分数都留着，回放就是按那版参数复跑一次验证。
- **被回滚的版本不删**，标记 `status: "rolled_back"`，它仍是"这条假设被否证"的证据。

## 三、具体实施步骤

1. **新建 `evoundo.py`**，实现 `VersionChain`：
   - `add(version_id, proposal, score, parent_id)` → 追加一个版本
   - `best()` → 当前最优版本
   - `rollback(to_version_id)` → 把 current 指回去，返回被回滚的那一版
   - `to_dict()` / `dump(path)` → 版本树落盘（JSON）
   - `render_html(path)` → 一份能看到版本树的 HTML（父子关系、分数、状态），**不依赖任何前端库**
2. **接进 `research_loop.py`**：
   - 每次实验后 `chain.add(...)`
   - `Reviewer` 判 `reverted=True` 时，调 `chain.rollback(chain.best()['version_id'])`，并把动作写进事件
   - 结束时 `chain.dump()` 到 `artifacts/evoundo/<run_id>/versions.json` + `versions.html`
3. **事件里要能看到**：`rollback` 事件带 `from_version` / `to_version` / `reason`。

## 五、本阶段红线

- 回滚**不许**重新训练（那会改掉分数，等于伪造历史）
- 回滚**不许**删版本
- 不许把 `best` 改成"最后一版"（那是退步，不是回滚）
- 不许动 `executor.py` 的训练逻辑
