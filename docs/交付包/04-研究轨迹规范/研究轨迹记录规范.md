# 研究轨迹记录规范 v1.0

> 一句话：**轨迹不是日志，是证据链。**
> 判断标准只有一个——把这份记录交给一个没参与开发的人，他能不能不问人，就复现你的结论、并相信你的结论。

适用：EvoResearch 本体、验收测试、路演材料、知乎长文里的实验叙事。
两个比赛通用：字段分「核心区」和 `ext` 扩展区，换比赛只加字段、不改结构。

---

## 0. 为什么自进化系统必须留痕

自进化 Agent 的两个死结——稀疏奖励、灾难性退化——本质上都是**记忆不可信**：

- 没有轨迹，"上一轮 F1 是 0.86" 就只是一句模型自己说的话；
- 没有轨迹，"这次改动让分数变好了" 无法区分「真的变好」和「换了随机种子」；
- 没有轨迹，回滚只能回滚到"大概那个版本"，而不是一个可验证的快照。

所以 EvoUndo 的前提不是快照，是**每一轮都能被独立审计的记录**。

---

## 1. 三条设计原则

**P1 一轮一记录，只追加不修改。**
任何修正都是新版本（`revision` +1），旧版本保留。改写历史 = 轨迹作废。

**P2 每个论断必须挂数字。**
"缺失值处理得当" 不算证据；"加 5 个缺失指示变量，OOF F1 0.165 → 0.443，5 折同向 5/5" 才算。
规范里禁止出现没有数值锚点的结论句。

**P3 记录成本 ≤ 3 秒/轮，全部自动采集。**
靠人手填的轨迹一定会烂。Manager 落库、Reviewer 校验，人只做两件事：写假设、签收结论。

---

## 2. 记录单元

一轮 = 一个原子干预 = 一条 `round_record.json`。

```
runs/<run_id>/                      # 一次完整研究任务
├── run.json                        # 任务级元信息、预算总额、目标
├── data/
│   ├── input.parquet               # 原始数据只读副本（或 sha256 指针）
│   └── splits/fold42.json          # 划分索引（固定，可被任何人重建同一划分）
├── rounds/
│   ├── r000_baseline/round_record.json
│   ├── r001_missing_indicator/round_record.json
│   ├── r002_tune_depth/round_record.json
│   └── r003_revert/round_record.json
├── artifacts/                      # 模型文件、混淆矩阵图、日志（只放指针也可）
├── trace.jsonl                     # 全部轮次的哈希链，一行一轮
└── report.md                       # 面向人的最终报告
```

`trace.jsonl` 每行：`{"round": n, "round_id": "...", "prev_hash": "...", "hash": "..."}`。
链式哈希 = 事后改任何一轮，后面全部对不上。

## 3. 每一轮必须留的九项证据

缺任何一项，这一轮**不计入研究轨迹**（验收时按「无效轮」扣分，见验收表 `3-轨迹评分`）。

| # | 证据 | 关键字段 | 最低强度 | 没有它，会被这样质疑 |
|---|---|---|---|---|
| 01 | **身份与血缘** | `round_id` `parent_round_id` `started_at` `status` `chain.prev_hash` | E2 | 「这轮是哪一轮？凭什么说它是后来那轮的原因？」 |
| 02 | **输入快照** | `input.sha256` `rows` `cols` `target` `pos_rate` `split.split_hash` `split.seed` | E3 | 「你换了数据 / 换了划分吧？」 |
| 03 | **假设与可证伪预测** | `hypothesis` `expected_direction` `falsifier` `confidence_before` | E1 | 「先跑再看结果编故事」 |
| 04 | **干预清单（diff）** | `intervention.diff[]`（字段级增删改）`kind` | E2 | 「你到底改了什么？」 |
| 05 | **执行凭证** | `exec.command` `code_commit` `env_hash` `exit_code` `duration_s` `log_path` | E3 | 「这个分数是手填的吧？」 |
| 06 | **结果与不确定性** | `result.value` `per_fold[]` `std` `ci95` `confusion` `delta` `mde` | E3 | 「一次运气好也算提升？」 |
| 07 | **闸门与回滚** | `gates[]`（每条 pass/fail）`redlines[]` `reverted` `restored_from` | E2 | 「坏了也没人拦，越改越差」 |
| 08 | **预算台账** | `budget.tokens_in/out` `cost` `wall_s` `experiments_used` `cumulative` `cap` `reconciled_with` | E2 | 「预算守住了吗？谁记的账？」 |
| 09 | **结论与下一步** | `verdict`(kept/reverted/failed) `reason`(含数字) `next_hypothesis` `carry_over[]` | E1 | 「所以呢？下一轮干嘛？」 |

### 强度分级（写进字段 `evidence_level`）

| 级别 | 含义 | 判定方法 |
|---|---|---|
| **E0** | 声明 | 只有文字，无数字 |
| **E1** | 可复算 | 有数字和口径，换个人用同一份代码能算出同一数 |
| **E2** | 可复现 | 同 seed 重跑，指标差 ≤ 1e-6（确定性）或 ≤ 0.01（有随机性） |
| **E3** | 可审计 | 第三方只凭记录（不看你的环境）能重建数据、划分、模型，得到同结论 |

**验收只看 E2 以上。** E1 的记录可以留在轨迹里，但不能作为「提升」的依据。

### 九项的最小可行集（赶时间时）

只保 02 / 04 / 05 / 06 四项，也能撑住「可复现」；
但 03 和 07 一旦缺，路演时评委最想看的「它为什么这么改」「改坏了怎么办」就没了——这两项是叙事核心，不能省。

## 5. 三条硬约束（不然轨迹只是自说自话）

**H1 链式哈希。** `hash = sha256(canonical_json(record 去掉 chain.hash))`，`prev_hash` = 上一轮 hash。
任何一轮被改，`validate_trace.py` 立刻在那一轮报 `CHAIN_MISMATCH`。

**H2 复现三元组。** `split_hash + split_seed + env_hash` 三者齐备，别人才能重建你的划分和运行环境。
只写 "random_state=42" 不够——库版本不同，同一个 42 也会给出不同结果。

**H3 预算双账。** 自己算的账（`budget.*`）必须和网关/调用日志的账（`reconciled_with`）对上，误差 > 1% 视为轨迹不可信。
这条是「预算遵守率」这个指标唯一能自证的方式。

## 6. 反例：这些不算证据

| 写法 | 为什么不算 | 改成 |
|---|---|---|
| `"F1 达到 0.86"` | 没折、没 seed、没数据版本 | `0.86 (5 折均值, seed=42, data sha256:6d1e…, std=0.01)` |
| `"做了特征工程，效果提升"` | 无 diff、无基线 | `+5 个 isna 指示变量；F1 0.165→0.443；5/5 折同向` |
| `"模型训练完成，耗时 3 秒"` | 没说是哪台机器、哪个 commit | `4.2s, 8 核/16G, commit a1b2c3, hist-gbdt max_iter=400` |
| `"预算还剩 7 次"` | 单一记账方 | `自记 6/20 次；网关日志 6 次；差 0` |
| `"回滚到最优版本"` | 没说是哪一轮、哪个 hash | `restored_from r002_class_weight, 回滚后复跑 F1 0.554（=原值）` |
| 截图一张 loss 曲线 | 不可复算、可 P 图 | 附 `metrics.json` 原始值 + 生成脚本 |

## 7. 自动校验

```bash
python validate_trace.py runs/demo_readmission            # 校验整个 run
python validate_trace.py runs/demo_readmission --strict   # E2 以下即失败
```

检查项：九项证据齐全、字段类型、哈希链连续、预算算术、`delta` 与 `per_fold` 自洽、复现记录存在。
退出码：0 = 通过，1 = 有 FAIL，2 = 有 WARN（`--strict` 下 WARN 也算失败）。

输出就是验收表 `03-轨迹评分` 那张表的机器版——**人工不用再复核一遍**。

仓库自带的 `runs/demo_readmission/` 是一个可跑的样本：5 轮真实实验（含 2 次回滚），
`python validate_trace.py runs/demo_readmission` 应输出「5 轮全部通过」。改任意一个数字再跑，会立刻报错。

## 8. 接进 EvoResearch 的位置

| 组件 | 动作 |
|---|---|
| **Manager** | 开轮：生成 `round_id`、继承 `parent`、冻结 `input.sha256` 与 `split`；收轮：写 `budget` 与 `verdict` |
| **Analyst** | 产出 `input.profile`（缺失率、类别分布、异常值计数）→ 自动进 02 |
| **Scientist** | **必须**先写 03（假设 + 可证伪预测），才允许提交实验；这是唯一强制人工/LLM 交界的字段 |
| **Experimenter** | 自动写 05；`tokens_in/out = 0`，写明「未调用 LLM」——这本身是卖点 |
| **Reviewer** | 跑闸门、算 `delta_significant`、给 verdict；不通过则写 07 的回滚记录 |
| **前端** | 直接渲染 `trace.jsonl`：一轮一张卡，卡片正面 = 03 + 06，背面 = 04 + 05 + 08 |

选阈值、跑 CV、算 CI 全部在 Experimenter 侧用 Python 做，**不烧 token**，所以轨迹记录的边际成本几乎为零。

## 9. 两个比赛的复用方式

| | 比赛 A（当前） | 比赛 B（复用） |
|---|---|---|
| 核心九项 | 原样 | 原样 |
| 数据快照 | CSV sha256 | 可能是数据库快照 → 换成 `snapshot_id` + 行数校验 |
| 预算 | token + 实验次数 | 可能加「真实金额」→ `budget.cost` 口径改 CNY |
| 扩展字段 | 放 `ext.*` | 放 `ext.*`，不改核心结构 |
| 校验脚本 | 一份 | 一份，零改动 |

关键：**扩展只走 `ext` 命名空间，核心区永不改动**。换比赛时 schema 的 `required` 列表一个字都不用变，这正是「可复用」的可验证含义。

## 10. 一页纸速查（贴墙）

```
一轮 = 九项：身份 输入 假设 diff 执行 结果 闸门 预算 结论
往上只追加，改了就新版本；每轮挂 sha256，链断了整条作废
每个论断后面必须跟：数字 + 口径 + 折数 + seed + 数据 hash
提升要过两道门：Δ > MDE（约 1.5×SE），且多数折同向
预算记两本账，误差 >1% 作废
回滚必须写清 restored_from 到哪个 round_id
```
