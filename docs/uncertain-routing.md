# 分类不确定时的高级复核

V15 在协作路由中，分类类别未知、置信度低于0.70、数值无效或分类接口失败时升级一次高级模型。传入原始问题、任务、训练集概况、原分类结果和不确定原因。高级模型只能返回白名单类别、low/high 派发目标和简短理由，不能更改预算、工具或直接生成研究答案。

高级模型可以 dispatch、clarify 或 missing_data。dispatch 仍需工作站实际执行；clarify 返回必要问题，missing_data 说明缺口。格式不合法、接口失败或剩余预算不足时明确阻塞，不能把基线结果当成研究完成。所有工作站均失败也不再调用最终审核生成研究结论。先前真实基线保留在开发者记录中。

高级复核最多一次，计入共享调用/Token/时间预算，并预留工作站执行与最终审核所需调用。高级执行次数预算继续约束实际高成本工作站，不把一次复核悄悄算作免费调用。高成本单模型对照不经过分类站，因此不触发此升级。

页面展示分类不确定→高级模型复核→重新派发→实际执行。无法判断时状态 needs_input，其他受阻为 blocked，停止轮询并显示问题/原因，预测输出为空，最终测试集不打开。设置阈值、模型及计费边界显示在开发者面板。

验证：34项测试通过。真实API故障注入测试将实际分类输出置信度调低至0.1，成功触发高级复核、派发、工作站实验和最终审核，输出1000条验证样本预测；另一次高级复核接口失败时正确停止，没有生成预测结论。此测试不声称分类站自然给出低置信度。
