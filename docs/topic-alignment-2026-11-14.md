# Research Agent 赛题核查与完善

核查口径：以用户 2026-11-14 补充的四条 comment 为准。本地轻量模型不是必要条件；重点是 Agent 如何在资源约束下完成研究，以及如何评估系统自己的改进。

## 逐项核查

| 赛题要求 | 原有问题 | 本轮落实与证据 |
|---|---|---|
| 规划—证据—假设—实验—验证—修正 | 有五角色实现，但策略 pin 只是记录；云端直接路由提案没有执行 | `agents.py` 将策略接到实际 prompt；`research_loop.py` 执行云端提案并反馈真实 verdict / 类别指标 |
| 单个 LLM 支持多角色 | 默认文案和入口依赖本地千问，升级还强依赖另一家 Jev | 新 `/research-agent` 入口；`model_budget.py` 各角色共享同一个 client；新验收采用明确署名的程序证据门，不冒充 Jev 调用；旧分层模式保留 |
| 按反馈与预算调用模型 | 部分失败调用不计数，字符串适配器丢 usage，额外验证可能绕预算 | 运输前预留调用；未知 usage 保留预算；角色共享调用 / token / 截止时间；统计、训练、评审不调用模型；诊断只读取开发证据 |
| 实际研究任务 | CSV 分类执行器已有真实训练；提案无法传预处理 | 增加有界预处理字段及类型验证，并传到真实执行器；内置 noisy-moons 分类作为轻量、可复现评测 |
| 自进化 | 候选模块独立，演示使用模拟模型响应，缺少完整连续实验 | `research_system.py` 连续两轮开发、候选冻结、同任务新旧对照、升级 / 拒绝、独立上线监控；新旧每臂最多 3 次训练 |
| 系统自身评估 | 调用比较漏云端，缺完整完成度 / token / 时间门槛 | 同时检查匹配任务、完成度、合法率、重复率、质量、全部模型调用、真实 token 和墙钟；检查 criteria 摘要，NaN / 未知指标不通过 |
| 可回退自动化 | 可疑高分可能被历史 max 当成最终最优与回滚目标 | 最终报告使用真正被接受的版本；退化 / 可疑实验回到先前接受版本；上线冻结监控规则；页面可恢复上一稳定策略 |
| 可追溯、可复现 | 旧导出与新运行未打通 | 每次保存数据 SHA256、环境版本、冻结条件、事件、轨迹、策略版本；启动时快照源代码及其 SHA256；导出快照，不使用事后变化的源码 |

## 新入口与运行

`start-research.ps1` 在已有依赖环境启动 API，页面路径 `/research-agent`。原数据工作台 `/`、原演示 `/demo` 均保留。

新 API：`GET /system/config`、`POST /system/campaigns`、`GET /system/campaigns/{run_id}`、`POST /system/campaigns/{run_id}/rollback`、`GET /system/campaigns/{run_id}/export`。

每轮先用开发数据研究，再生成并冻结候选。候选生成器看不到验收任务分数。第一轮验收任务种子 101 / 202；第二轮换成 303 / 404，避免把上一轮验收任务不断当训练数据。两臂使用同数据与同训练预算，轮次间交替执行顺序。开发种子 11，最终审计种子 999，每份任务固定 60/20/20 划分，测试集不用于候选或模型选择。

可以上传自己的开发 CSV；策略验收仍限于内置独立分类任务。因此不能将验收结论推广为对上传数据或任意领域都有效。

## 真实验证结果

证据目录 `artifacts/topic-delivery-verified/`，独立重跑目录 `artifacts/topic-delivery-replay/`。结果由实际 sklearn 预测产生，没有调用外部模型。

| 指标 | 实测结果 |
|---|---|
| 策略迭代 | 2 轮 |
| 第一轮 | 平均验证宏 F1 提升 0.05839588933316153，通过门槛并升级 |
| 第二轮 | 测试压缩规划上下文，验证分数变化 0；因规则模式无真实模型 token 可节省，缺少改善证据，保留原策略并拒绝候选 |
| 真实训练 | 39 次，包含开发、两臂验收、上线监控及最终审计 |
| 模型调用 / token | 0 / 0；这是无模型程序基准，不是模型效率成绩 |
| 最终独立审计测试宏 F1 | 0.899749373433584，只在全部策略决策结束后打开一次 |
| 独立重跑 | 两轮质量差值、最终测试指标和数据摘要一致；墙钟允许变化 |
| 回归测试 | `python tools/run_offline_checks.py`，282 tests OK，日志 `artifacts/topic-regression-final.txt` |
| 新增关键测试 | 多角色共享预算、失败预留、未知用量、策略 prompt 生效、云端方案执行、可疑高分回滚、冻结评测条件、匹配任务、真实两轮、低训练预算停止、API 处理函数串联、ZIP 导出及人工恢复 |

规则模式第一轮从同族正则调参切到不同模型族探索；第二轮测试上下文压缩。二者均为明确标注的程序策略。单模型模式会使用同一个真实模型生成实验与策略候选，并复用相同执行器和门槛，绝不将规则文本标为模型输出。

## 不能宣称已完成的验证

1. **真实云端模型能力与 token 节省效果未验证**。本次没有外部模型调用，不能从 0 token 推导出模型成本改善。真实费用在未取账单时为 unknown。
2. **HTTP / 浏览器端到端未验证**。执行环境连本机 TCP 也被禁止，实测 `socket.connect(127.0.0.1)` 抛 `WinError 10013`，Starlette TestClient 卡在 asyncio 的 socketpair 初始化。完整原测试套件因此中止；282 项是明确选择的离线回归，不是全套测试数量。新 API 的同步处理函数、后台任务、状态读取、导出和恢复已实际串联测试。JS 语法检查通过。
3. Edge 无头静态截图尝试未生成结果，因此不声称完成了视觉验收。
4. 每轮两份验收任务是冒烟评测，不能作为统计显著的跨域可进化证明；需扩展任务族、种子与预算消融。
5. 时间策略是不再启动新工作；已经开始的 sklearn 训练不强制终止。token 准入使用保守 UTF-8 字节估算，实际 usage 单独记录；无法保证所有供应商 tokenizer 均满足严格上界。
6. 模型预算按 campaign 共享，并非供应商账户级配额；当前 API 是仅本机开发服务，不是多租户部署。

## 复现命令

```powershell
python tools/run_research_system.py --output artifacts/a-new-run
python tools/run_offline_checks.py
node --check static/research-agent.js
```

在允许本机网络的环境，还需要执行 `python -m unittest discover -s tests` 和浏览器联调。重放应使用新目录，禁止覆盖已有证据。导出包包含运行时源代码快照、协议、数据与输出；模型接口非确定时，重跑不保证文本或结果逐字一致。
