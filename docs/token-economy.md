# 节省模式

用户目标改为：研究交付质量接近高成本模型，优先节省 Token 和模型费用，不为微小 F1 提升无限追加实验。

## 本次改动

- 同一研究、数据、目标及能力边界未变化时复用第一次有效派发；工作站失败或连续停滞后重新分类。不跨数据集缓存路由，首次低置信度仍交高级模型复核。
- 最终审核只接收一次实验配置、实际成绩、分组统计、类别指标、局限、下载引用及当前最佳；删除重复的特征审查元数据、先前答案和已生成的模板答案。完整审计日志继续保存，未缩减真实统计证据。
- 后续实验只接收上一轮结果摘要；历史经验保留必要配置和实测结论，避免重复整段背景。
- 在平台期用一个高级候选替代继续低成本调参；已有历史最佳且新尝试未提升时提前结束。回退机制、共享预算、最终高级审核和真实预测文件保留。
- 页面默认发送 `economy:true`，按钮标为“节省模式”；API 省略该字段仍保留旧行为。开发者对比默认将节省模式与全高成本模型比较，两组预算上限相同，内存经验均关闭。

不能承诺未知任务的 F1 永远与高成本模型相差不超过 0.005；这是本次小范围验收的预设检查标准，不是生产系统提前知道的答案。没有同时运行昂贵对照来判断每个用户任务的差距。
