# V21：有边界的路由恢复与回答补齐

基于已应用 V20 的原项目构建。修改与测试均在 `C:\workspace\EvoResearch-v19-review` 完成；原工程不在本轮可写范围，未部署到 8018。

## 已实现

1. `clarify` 恢复仅适用于问题明确包含现有字段、且询问关联/因果/影响关系的情况。字段名可来自路由回复，也可从原问题与现有字段/已知中文别名精确匹配，最多 3 列。真正缺数据、研究目标不清、无关字段不能靠基线 F1 强制报完成。
2. 符合上述条件时执行真实训练集描述性分组统计，结果仍为限定范围的 `partial_completed`；不生成客户预测、不评最终测试集、不声称因果成立。高级模型明确返回 `missing_data` 时不覆盖。
3. 所有正式研究回答和追问统一使用证据补齐。原 V19/V20 正式回答本就调用 present_answer，问题是默认内容未补全，并非该函数只用于追问。
4. 附加数字来自实际 outputs：预测条数、有效验证 F1、关联训练行数及已计算分组 n/比例。程序不生成直接结论来替代模型；缺直接回答保持 revise。
5. 验证预测说明“参与方案选择、不是独立最终测试、不是未来客户、特征重要性不证明因果”；明确 calibration_performed=false 才说未校准，否则说状态未记录。
6. 下载仅接受调用方提供、属于预测输出的内部链接；关联分析不附预测链接。原文里的未核验预测链接也移除。比较分支没有用户运行的下载端点，不伪造端点。
7. 已知字段面向技术用户中文＋英文原名，面向运营用户保留中文；不猜测未知字段中文含义。
8. 字数不足以同时保留直接回答和完整边界时标记 character_budget_too_small/revise；完整事实保留在 answer_evidence，不静默删掉边界后仍标完成。
9. answer_evidence 的 direct_answer_verified=false 明确表示：程序补齐不是对自然语言答案真实性的独立验证。没有声称可自动发现一切事实矛盾。
10. 版本升级为 ml-chain-21，前端握手同步，加载指纹增加 answer_evidence.py。
